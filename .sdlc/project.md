## 2. Architecture

```
taskctl (CLI binary)
│
├── main.go          — CLI entry-point, flag parsing, subcommand dispatch
│     run()          — testable root; called by main() with os.Args / os.Stdout
│     runAdd()       — "add" subcommand handler
│     runList()      — "list" subcommand handler
│     runDone()      — "done" subcommand handler
│     runDelete()    — "delete" subcommand handler
│     runStats()     — "stats" subcommand handler
│     runClear()     — "clear" subcommand handler
│
└── task/task.go     — domain model + persistence library (no CLI coupling)
      Task{}         — data record: ID, Title, Done, Priority, DueDate
      Manager{}      — owns filePath, sync.Mutex, optional createTemp hook
      NewManager()   — constructor; enforces all path-safety invariants
      load()         — read + post-deserialisation-validate JSON from disk
      save()         — atomic write-to-temp + fsync + rename
      Add()          — validate inputs, load, append, save
      List()         — load, filter by priority and/or overdue
      Complete()     — load, mutate Done=true, save
      Delete()       — load, filter-out by ID, save
      Clear()        — load, partition done/pending, conditional save
      Stats()        — load, single-pass aggregation → Stats{}
```

### Layering rules
- `task/` has **no dependency on** `main.go`. It is a pure library.
- `main.go` owns all user-facing formatting and flag parsing.
- All stdout/stderr stays in `main.go`; `task/` only uses `log.Printf` for non-fatal warnings.

### Concurrency model
- `Manager` embeds `sync.Mutex`; every exported method acquires it with `defer m.mu.Unlock()`.
- The lock covers the **entire load → mutate → save** sequence (no TOCTOU window).
- **Known gap (TODO #17):** no OS-level file lock — two separate processes are not serialised.

## 4. Key Patterns

### 4.1 Testable entry-point
`main()` calls `run(os.Args, os.Stdout)` and exits on error. Every `runXxx` handler accepts `io.Writer` and returns `error` — never calls `os.Exit` directly. This makes 100% of CLI logic unit-testable without subprocess overhead.

### 4.2 Atomic save (write-to-temp + rename)
`save()` sequence:
1. `createTemp(dir, "tasks-*.tmp")` — sibling temp file in same directory
2. `tmp.Chmod(0600)` — lock permissions before writing any data
3. `tmp.Write(data)` — write marshalled JSON
4. `tmp.Sync()` — fsync (crash-safe)
5. `tmp.Close()`
6. `os.Rename(tmpName, m.filePath)` — atomic on POSIX

`defer os.Remove(tmpName)` cleans up on any error path. The target file is never partially written.

### 4.3 Interface injection for error testing
`Manager.createTemp` is `func(dir, pattern string) (osFile, error)`. When `nil`, defaults to `os.CreateTemp`. Tests inject stubs (`chmodFailFile`, `syncFailFile`) to cover Chmod/Sync failure branches without filesystem manipulation.

```go
type osFile interface {
    Chmod(os.FileMode) error
    Write([]byte) (int, error)
    Sync() error
    Close() error
    Name() string
}
```

### 4.4 Defense-in-depth path validation (single authoritative layer)
`NewManager` is the **sole** path-safety gate. `main.go` delegates entirely — no duplicated checks:
1. `filepath.Clean` — normalise
2. `filepath.IsAbs` — reject absolute paths
3. `strings.HasPrefix(clean, "..")` — reject obvious traversal
4. `os.Getwd()` + `filepath.EvalSymlinks` + `evalSymlinksPartial` fallback — detect symlink traversal (Fixes #87)
5. Prefix check: resolved path must be rooted inside `cwd`

### 4.5 Post-deserialisation validation in `load()`
After JSON unmarshal, every record is checked: positive ID, non-empty title, known priority, valid/empty due date, no duplicate IDs. Prevents a hand-crafted `tasks.json` from corrupting state (Fixes #80).

### 4.6 Global `--file` flag pre-scan
`run()` manually pre-scans `args[1:]` for `--file path`, `-file path`, `--file=path`, `-file=path` before subcommand dispatch — so the flag works both before and after the subcommand name. Consumed tokens are spliced out of the slice.

### 4.7 Per-subcommand `flag.FlagSet` with `ContinueOnError`
Each `runXxx` uses `flag.NewFlagSet("cmd", flag.ContinueOnError)` so parse errors are returned, not `os.Exit(2)`.

### 4.8 Unicode-safe title length
`utf8.RuneCountInString(trimmed) > maxTitleLength` (1000 runes), not `len()` bytes — emoji are counted correctly (Fixes #69).

### 4.9 ID allocation with overflow guard
Next ID = `max(existing IDs) + 1`. If `nextID <= 0` after increment, `Add()` returns an overflow error (Fixes #70). IDs are never reused after deletion.

### 4.10 Completion rate rounding
```go
pct = (s.Completed*100 + s.Total/2) / s.Total
```
Half-up integer rounding: 2/3 → 67%, not 66% (Fixes #134).

## 5. Invariants

Properties that must hold at all times. Any PR breaking one must be rejected.

| # | Invariant | Enforced in |
|---|---|---|
| I-1 | Task IDs are positive integers (`id > 0`) | `Add`, `Complete`, `Delete`, `load`, CLI handlers |
| I-2 | Task IDs are unique within a store | `load` post-deserialisation |
| I-3 | Task IDs are monotonically increasing, never reused | `Add` ID allocation |
| I-4 | Priority ∈ `{"low", "medium", "high"}` | `Add`, `List`, `load`, CLI |
| I-5 | Title is non-empty after `strings.TrimSpace` | `Add`, `load` |
| I-6 | Title ≤ 1000 Unicode runes | `Add` |
| I-7 | Due date is `""` or matches `"2006-01-02"` | `Add`, `load`, CLI |
| I-8 | Tasks file permissions are `0600` | `save` via `Chmod` before first write |
| I-9 | Tasks file is never partially written | `save` atomic rename |
| I-10 | `Manager.filePath` is always a relative path inside cwd | `NewManager` full chain |
| I-11 | Mutex held for full load→mutate→save sequence | All exported `Manager` methods |
| I-12 | `Clear` does not write to disk when no tasks are done | `Clear` early-return guard |
| I-13 | `HighPriority + MediumPriority + LowPriority == Total` | `Stats` single-pass |
| I-14 | `Completed + Pending == Total` | `Stats` single-pass |
| I-15 | Completed tasks are never flagged overdue | `IsOverdue` checks `t.Done` first |

## 7. Test Strategy

### 7.1 Test layout

| File | Package | Scope |
|---|---|---|
| `task/task_test.go` | `package task` (white-box) | All `Manager` methods, `IsOverdue`, `NewManager` path validation |

| `main_test.go` | `package main` (white-box) | All `runXxx` handlers and `run()` dispatch |

### 7.2 Test isolation
Every test uses `t.TempDir()` + `os.Chdir()` via the shared `chdirTemp(t)` helper. The original working directory is restored in `t.Cleanup`. Each test has a private, hermetic filesystem scope.

### 7.4 Test categories

**Happy-path CRUD**
`TestAdd`, `TestList`, `TestComplete`, `TestDelete`, `TestSaveAtomicity` (20-cycle sequential add+list)

**Boundary / validation**
- Empty/whitespace titles (4 variants), invalid priorities (5+ values)
- Unicode rune counting at limit and over limit (`TestAddUnicodeTitleAtLimit/OverLimit`)
- Due date format and max-length guards
- Zero and negative IDs for `done` and `delete`

**Path safety**
- Absolute paths (3 cases), `..` traversal (3 cases)
- Symlink pointing outside cwd → rejected; symlink inside cwd → accepted
- `foo..bar` filename accepted (regression guard for old substring check)

**Error paths**
- Non-existent ID for `Complete`/`Delete`
- Corrupted JSON: `Clear` leaves file unmodified; error includes file path
- `save()` failures: `CreateTemp`, `Rename`, `Chmod`, `Sync` (all via injection)

**Overdue logic**
- Past date, future date, done task, no due date, today (UTC), yesterday
- Today test uses `UTC+14` timezone to stress timezone handling (Fixes #58 regression guard)

**Stats correctness**
- Per-priority breakdown, completed/pending split, overdue excludes done tasks
- Rounding: 2/3 completed → 67% (Fixes #134)

**CLI flag parsing**
- `--file` before/after command, `=` syntax, single-dash, missing value → clear error (Fixes #130)
- Path length guard > 4096 chars
- `--version`, `-version`, `version` subcommand
- Round-trip: write to `custom.json`, read back, verify `tasks.json` not created

**Output format**
- Exact string matches for `runClear` (plural/singular "task/tasks")
- `[x]` marker rendered for done tasks in `runList`

## 8. Security Posture

| Control | Implementation |
|---|---|
| Path traversal prevention | `NewManager`: IsAbs + `..` prefix + EvalSymlinks chain |
| File permissions | `save()` always `chmod 0600` before first byte written |
| Input length limits | `maxFilePathLen=4096`, `maxDueDateLen=10`, `maxTitleLength=1000` |
| No external dependencies | Zero supply-chain attack surface |
| Atomic writes | No partial-write window |
| No hardcoded secrets | Verified: no credentials, tokens, or API keys in codebase |
| Logging | `log.Printf` for warnings only; no sensitive data logged |
